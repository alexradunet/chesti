## User outcome / bounded design
A user can find and select a valid reference target even when it is older than the first 200 candidates. Reuse the existing native object-search dialog and bounded lookup endpoint; scope results to the reference target type. Support object-editor single/multiple reference controls, published board reference actions and parameterized view input selection. Selecting a result changes only the existing form control; it must not save, navigate, publish, or generate. Existing native dropdowns remain usable without JavaScript at their documented 200-per-type-plus-selected bound; full-collection typed search is a progressive enhancement, like existing writing-link search. Do not replace native selects with a custom combobox framework, build autocomplete-as-you-type, or add a dependency.

## Current state / excerpts / conventions
- `src/objects/http.ts:223–234` handles JSON lookup (reopened at the refreshed base):
```ts
requireFields(url.searchParams, ['q']);
const search = url.searchParams.get('q') ?? '';
if (search.length > 200) throw new AppError(422, 'Search must be at most 200 characters.');
const rows = objects.listObjects({ search, limit: 51 });
const result: ObjectLookupResult = {
  items: rows.slice(0, 50).map(record => ({ id: record.id, title: record.title, typeName: objects.getType(record.typeId).name })),
  truncated: rows.length > 50,
};
```
Return shape is defined by `ObjectLookupSchema` in model.ts (IDs/titles/type names only, at most 50). All responses have no-store. Runtime list query validates IDs/search and excludes Trash.
- `src/objects/render.tsx` `PropertyControl` renders ordinary single/multiple reference `<select>` values; `InlineAction` uses the same component with `name="value"`. `View` renders a separate `select[name="input"]` for its input object. Plans 007/009 now supply the typed native pools and case-insensitive selection; keep them.
